# friday-mail: 金曜日の案内メールを作る

入力: `$ARGUMENTS`（その週の質問ファイル名。例: `質問_1107.md`）

## 0. 準備

1. 引数が空なら、`自分の業務/` にある `質問_*.md` の一覧を見せて、どれを使うかユーザーに聞く。推測で選ばない。
2. ファイル名だけ渡されたら `自分の業務/<ファイル名>` を読む（`.md` が無ければ補う）。見つからなければ止めて伝える。
3. ファイル名の `MMDD`（例: `1107`）を、この週の日付として以後のファイル名と件名に使う。
4. 次を必ず読む。**ルールの正本は `業務文脈.md`**。このスキルと食い違うときは `業務文脈.md` に従う。
   - `業務文脈.md`（役割・ルール1〜8・判断の例）
   - `自分の業務/wiki_一覧.md`（答えと担当を探す唯一の出典）
   - 一番新しい `自分の業務/案内メール_*.md`（メールの形の見本。ルール8）

## 1. 質問を整理する（業務文脈.md ルール2・3・4・6・7）

質問ファイルの各項目を1つずつ見て、次のどれかに振り分ける:

- **メールに入れる質問**: 言い方が違っても聞いていることが同じなら1つにまとめる（ルール2）。
  - `wiki_一覧.md` に該当があれば、答え・Wikiの場所・担当をつける（ルール3）。
  - 該当がなければ答えを作らず「要確認」にする（ルール4）。一般常識や推測で埋めない。
- **メールに入れないもの**: 個人的な事情・気持ち（ルール7）、前置きやあいさつなど質問ではないもの。

人の名前（「新入社員B」「先輩C」など）はどこにも書かない。役割で書く（ルール6）。

## 2. 整理表を書く → `自分の業務/質問と回答_MMDD.md`

既存の `自分の業務/質問と回答.md` と同じ構成で書く:

- 見出し `# 質問と回答 (期間)`、元データ・答えの出典
- `## 質問と回答` の表: `# | 質問 | 答え | Wikiの場所 | 担当 | 元の質問`
  - 「元の質問」は日付と経路（チャット / 先輩経由 番号）で書き、名前は書かない。まとめたものは「（まとめた）」
- `要確認の項目:` の一覧（なければ「なし」）
- `## メールに入れなかったもの` の表: `元の質問 | 扱い | 理由`（理由にルール番号を添える）
- `## 確認が必要な点（オンボーディング担当）`

## 3. 案内メールの下書きを書く → `自分の業務/案内メール_MMDD.md`

見本のメールと同じ順・同じ言い回しで書く（ルール8）:

```
件名: [最初の週のご案内] 今週いただいた質問と来週の準備 (M/D)
宛先: 新入社員 / CC: チーム長

お疲れさまです、オンボーディング担当です。今週もお疲れさまでした。

1. 今週いただいた質問
- <質問>
  <答え>。(Wiki: <場所>、担当: <担当>)
- <Wikiにない質問>
  要確認（Wikiに記載なし。オンボーディング担当が確認します）

2. 来週の準備
- 【要記入: M/D〜M/Dの予定】

困ったら先輩か私にいつでもメッセージをください。最初の週は、何を聞いても大丈夫です。
オンボーディング担当より
```

- 質問1つにつき2行（ルール5）。答えは短く。
- 「2. 来週の準備」の予定は手元の資料にないので、作らずに【要記入】で残す（ユーザーが予定を伝えた場合だけ埋める）。
- 件名の日付は質問ファイルの週の金曜日。

## 4. 確認して報告する

書き終えたら、次を自分で確認してからユーザーに報告する:

- [ ] 質問ファイルのすべての質問が、メールの項目か「メールに入れなかったもの」のどちらかに入っている（完了の基準）
- [ ] すべての項目に「答え」か「要確認」がついている
- [ ] 答えの中身はすべて `wiki_一覧.md` に書いてあることだけ
- [ ] 人の名前が整理表にもメールにも残っていない
- [ ] 1項目2行、見本と同じ順番

報告では、作った2ファイルのパス、まとめた質問、要確認の項目、メールから外したもの、【要記入】の箇所を短く伝える。

**メールは送らない。** 下書きを作るまでがこのスキルの仕事で、送信はユーザーが確認してから行う。
